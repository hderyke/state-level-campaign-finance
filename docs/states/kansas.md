## Raw Data Structure

One PDF per candidate per filing period, stored in `data/Kansas/raw/`. File naming follows GEC conventions: `{filer_code}_{period_code}.pdf` (e.g. `SW01JX_amend2007.pdf`). Total: ~3,600 PDFs.

Two PDF formats exist depending on how the committee filed:

| Format | Description |
|---|---|
| Scanned (OCR) | Physical paper forms scanned and uploaded to GEC. Text extracted via `pdfplumber` with bounding-box heuristics. Lower fidelity — some fields missing, name OCR errors common. |
| Web-form | Reports generated by the GEC's online portal. Each page header reads "Campaign Finance Schedule A Report Page X of Y". Consistent column layout at predictable x-coordinates. |

Each PDF contains one or more schedules:

| Schedule | Content |
|---|---|
| Schedule A | Contributions received |
| Schedule B | In-kind contributions |
| Schedule C | Expenditures |
| Schedule D | Other transactions (loans, adjustments) — parsed but not stored |

A companion `manifest.csv` tracks which (filer, period, amendment) combinations have been downloaded.

## Scraper

`src/pipeline/scrapers/kansas.py`

Scrapes the GEC campaign finance index page for all active filer links, then downloads the full report history for each filer. For each (filer, period), only the latest amendment is kept — the scraper detects "amend" in the filename and skips earlier amendments when a newer one exists.

**Limitations:**
- Only **candidate committees** are available via the GEC public PDF index. PACs, party committees, and other filer types file separately through a different GEC portal that does not publish public PDFs. The `non-candidate committees` table in the KS database is always empty.
- No bulk export — each PDF must be downloaded individually (~3,600 requests for a full run).

**Expected runtime:** ~20–30 min for a full scrape, ~5–10 min incremental (current filers only).

## Parser

`src/pipeline/parsers/kansas.py`

PDF text extraction via `pdfplumber`. All pages are extracted and classified by schedule; the contribution and expenditure rows are then parsed from the schedule-specific page subsets.

**Page classification (`_page_schedule`):**  
Each page is classified as Schedule A, B, C, or D based on whether the string "SCHEDULE A" (etc.) appears in the page's text. Pages without a matching header are unclassified.

**PLF/GLF fallback:**  
Pre-General Last-Minute (PLF) and General Last-Minute (GLF) filings are single-section PDFs with no schedule header. Detected from the filename period code via regex. All pages in these files are treated as Schedule A.

**Contribution extraction (`_parse_schedule_a`, `_parse_schedule_b`):**  
Anchors on date-shaped tokens in the left column (~x≈50), then clusters nearby text into name / city / state / zip / amount fields using bounding-box proximity. Amount detection uses a minimum threshold (`A_AMT_MIN = 350`) to avoid treating page numbers as dollar amounts.

**Expenditure extraction (`_parse_schedule_c`):**  
Same approach as contributions, with a separate amount threshold (`C_AMT_MIN = 350`).

**Deduplication:**  
Some amended PDFs embed the full schedule section twice (original + amendment copy in the same PDF). After parsing all pages, contributions are deduplicated on `(date, amount, contributor_name, contributor_city, transaction_type)` and expenditures on `(date, amount, payee_name, payee_city)` within each file.

**ZIP normalization:**  
`utils.clean_zip()` is applied to all `contributor_zip` and `payee_zip` values to strip trailing hyphens from incomplete ZIP+4 entries (e.g. `"67202-"` → `"67202"`).

**person_id model:** `name_hash` — GEC assigns no numeric filer ID. A stable 14-digit integer is derived from `MD5("KS|" + normalized_name)` prefixed with Kansas's FIPS code (20).

**Limitations:**
- Scanned-form OCR fidelity varies: some names come through garbled (e.g. "STCPHCN B OWENS" instead of "STEPHEN B OWENS"), some address fields are blank.
- No contributor type, employer, party, or incumbent fields in source PDFs.
- `occupation` is extractable from web-form PDFs only (~30% fill rate overall).
- `payee_city/state/zip` fill rate ~77% — lower for older scanned filings.
- 1 parse error per full run (unidentified PDF); see `parse_completed` error count in logs.

**Expected runtime:** ~32 min (3,600+ PDFs via pdfplumber).

## Data Notes

- **No non-candidate committees** — GEC's public PDF index covers candidate committees only. The `non_candidate_committees` table in `kansas.db` is always empty by design.
- **No expenditure type codes** — Schedule C contains payee name, date, amount, and a free-text purpose field only. `transaction_type` is 0% filled for all expenditures; `purpose` fills at ~81%.
- **No contributor type codes** — the source PDFs do not include a standardized contributor type column. `contributor_type` is 0% filled for all contributions.
- **"GROUP" payee** — a payee name "GROUP" ($539K to Kris Kobach) appears in the top expenditure recipients. Likely an OCR artifact where only a partial word was captured from the vendor name. Not fixable without re-OCR.
- **"Record News" / "Recordnews"** — the same publication appears under two name spellings due to OCR inconsistency across PDFs. Cross-file name normalization is not currently applied.
- **OCR name errors** — "STCPHCN B OWENS" appears instead of "STEPHEN B OWENS" due to a scanned-form OCR failure. These errors are in the source PDF text layer and cannot be corrected by the parser.
- **Barnett cross-file duplicate** — James A. Barnett's $480K contribution on 2017-12-22 appears in two separate PDF files (original + amendment filed as a separate document). Within-file dedup cannot catch this; the amount appears twice in the database. A cross-file dedup pass is not currently implemented.
- **Future-dated rows** — 1–2 rows with dates in 2027–2028 are present, almost certainly data-entry errors by filers. Not filtered.
- **Date string leaking into contributor name** — occasional web-form PDFs produce a contributor name like "12/8/2023 David Langford 12…" where the date field bleeds into the name column. Very low volume; not filtered.
- **Sarnecki $2M anonymous** — the $2M self-contribution by Philip Sarnecki (2025-12-31) has a blank contributor name, likely because the filer's name was not extractable from that PDF's layout.
